================================================================================
OPTIASSET ASSET MANAGEMENT SYSTEM - API DESIGN DOCUMENT
================================================================================
Version: 2.0 (Atomic-Scale Design)
Framework: FastAPI + PostgreSQL + SQLAlchemy
Authentication: JWT (OAuth2 Password Flow)
Authorization: Role-Based Access Control (RBAC)
Documentation: OpenAPI/Swagger UI (Auto-generated)
================================================================================

SYSTEM OVERVIEW
--------------------------------------------------------------------------------
Enterprise asset management system for tracking IT equipment inventory,
employee assignments, and maintenance lifecycle. Implements granular role-based
access control with two primary user roles: Admin and Employee.

TECH STACK:
- Backend: FastAPI (Python 3.11+)
- Database: PostgreSQL 15
- ORM: SQLAlchemy 2.0 (Async support ready)
- Authentication: JWT via python-jose
- Password Hashing: bcrypt
- Validation: Pydantic v2
- Documentation: Swagger UI / ReDoc (auto-generated)

================================================================================
AUTHENTICATION & AUTHORIZATION
================================================================================

ENDPOINT: POST /api/auth/login
Tags: [Authentication]
Summary: Authenticate user and retrieve JWT access token
Request Body: application/x-www-form-urlencoded
  - username (string): User email address
  - password (string): User password
Response: 200 OK
  {
    "access_token": "eyJhbGciOiJIUzI1NiIs...",
    "token_type": "bearer",
    "user_id": "uuid",
    "name": "John Doe",
    "email": "john@example.com",
    "role": "Admin|Employee",
    "permissions": ["all"] | ["view:assets", "view:my_gear"]
  }
Error Responses:
  - 401 Unauthorized: Invalid credentials
  - 400 Bad Request: Inactive user account

SECURITY SCHEME:
- Type: OAuth2 Password Flow
- Token URL: /api/auth/login
- Header Format: Authorization: Bearer <token>
- Token Expiry: 30 minutes

ENTITY 1: USER (System Users with Role-Based Access)
================================================================================

DATABASE MODEL: users
DESCRIPTION: System users who can access the platform with assigned roles
and permissions. Replaces legacy "Employee" entity.

FIELDS:
- id (UUID, Primary Key): Unique identifier
- role_id (UUID, Foreign Key → roles.id): Role assignment constraint
- name (String, Required): Full name of user
- email (String, Unique, Required): Email address for authentication
- hashed_password (String, Required): Bcrypt password hash
- is_active (Boolean, Default=True): Soft delete flag
- created_at (DateTime, Auto): Account creation timestamp

RELATIONSHIPS:
- belongs_to: Role (many-to-one via role_id)
- has_many: Assignments (one-to-many, cascade delete)

PERMISSIONS REQUIRED:
- manage:users - Create, update, delete users
- view:users - View user list and details

ENDPOINTS:

POST /api/users/
  Summary: Create new user account
  Access: Admin only (manage:users privilege)
  Request Body: application/json
    {
      "name": "Alice Johnson",
      "email": "alice@company.com",
      "password": "securePass123",
      "role_id": "uuid-optional"
    }
  Response: 201 Created
    {
      "id": "uuid",
      "name": "Alice Johnson",
      "email": "alice@company.com",
      "is_active": true,
      "created_at": "2024-03-07T10:30:00Z",
      "role": {"id": "uuid", "name": "Employee", "permissions": [...]}
    }
  Errors:
    - 400 Bad Request: Email already exists, invalid role_id
    - 403 Forbidden: Insufficient permissions

GET /api/users/
  Summary: Retrieve all active users with pagination
  Access: Admin only (view:users privilege)
  Query Parameters:
    - skip (integer, default=0): Offset for pagination
    - limit (integer, default=100): Max records to return
  Response: 200 OK
    [
      {
        "id": "uuid",
        "name": "Alice Johnson",
        "email": "alice@company.com",
        "is_active": true,
        "created_at": "2024-03-07T10:30:00Z",
        "role": {...}
      },
      ...
    ]

GET /api/users/{id}
  Summary: Retrieve specific user details
  Access: Admin only (view:users privilege)
  Path Parameters:
    - id (UUID): User unique identifier
  Response: 200 OK
    { user object }
  Errors:
    - 404 Not Found: User not found or inactive

PUT /api/users/{id}
  Summary: Update user information
  Access: Admin only (manage:users privilege)
  Path Parameters:
    - id (UUID): User unique identifier
  Request Body: application/json (all fields optional)
    {
      "name": "Alice Smith",
      "email": "alicesmith@company.com",
      "role_id": "new-uuid",
      "is_active": false
    }
  Response: 200 OK
    { updated user object }
  Errors:
    - 404 Not Found: User not found
    - 400 Bad Request: Invalid role_id, email conflict

PATCH /api/users/{id}/deactivate
  Summary: Soft delete user account (set is_active=false)
  Access: Admin only (manage:users privilege)
  Path Parameters:
    - id (UUID): User unique identifier
  Response: 200 OK
    { deactivated user object }
  Errors:
    - 404 Not Found: User not found

GET /api/users/{id}/assignments
  Summary: Retrieve assignment history for specific user
  Access: Admin only (view:users privilege)
  Path Parameters:
    - id (UUID): User unique identifier
  Response: 200 OK
    [
      {
        "id": "uuid",
        "user_id": "uuid",
        "asset_id": "uuid",
        "assigned_date": "2024-01-15T09:00:00Z",
        "return_date": null,

FIELDS:

ENTITY 3: ASSET (Company IT Equipment & Inventory)
================================================================================

DATABASE MODEL: assets
DESCRIPTION: Trackable company assets including laptops, monitors, furniture,
and other equipment. Supports status tracking and assignment history.

FIELDS:
- id (UUID, Primary Key): Unique identifier
- asset_tag (String, Unique, Required): Physical asset tag/label
- name (String, Required): Asset model/name
- status (String, Default="Available"): Current state
  - Enum: "Available", "Assigned", "Maintenance", "Retired"
- is_active (Boolean, Default=True): Soft delete flag
- created_at (DateTime, Auto): Creation timestamp

RELATIONSHIPS:
- has_many: Assignments (one-to-many, cascade delete)
- has_many: AssetStatusLog (audit trail)

BUSINESS RULES:
- UNIQUE constraint on asset_tag
- Status must match enum values
- Only Available assets can be assigned
- Assignment changes status to "Assigned"
- Return changes status back to "Available"

PERMISSIONS REQUIRED:
- manage:assets - Create, update, deactivate assets
- view:assets - View asset list and details

ENDPOINTS:

POST /api/assets/
  Summary: Add new asset to inventory
  Access: Admin only (manage:assets privilege)
  Request Body: application/json
    {
      "asset_tag": "LAPTOP-2024-001",

      "status": "Available",
      "is_active": true,

    - 400 Bad Request: Duplicate asset_tag

  Query Parameters:
    - status (string, optional): Filter by status

  Response: 200 OK

ENTITY 4: ASSIGNMENT (Asset-to-Employee Mapping with Audit Trail)
================================================================================

DATABASE MODEL: assignments
DESCRIPTION: Tracks temporary custody of assets assigned to employees.
Supports assignment date, expected return, and actual return tracking.

FIELDS:
- id (UUID, Primary Key): Unique identifier
- user_id (UUID, Foreign Key → users.id): Assigned employee
- asset_id (UUID, Foreign Key → assets.id): Assigned asset
- assigned_date (DateTime, Auto): Assignment timestamp
- return_date (DateTime, Nullable): Actual return timestamp

RELATIONSHIPS:
- belongs_to: User (many-to-one)
- belongs_to: Asset (many-to-one)

BUSINESS RULES:
- Asset must be in "Available" status before assignment
- User must be active (is_active=true)
- Assignment sets asset.status = "Assigned"
- Return sets asset.status = "Available"
- Each assignment creates audit log entry
- Prevent duplicate active assignments (same asset to multiple users)

PERMISSIONS REQUIRED:
- manage:assignments - Create/return assignments
- view:assignments - View assignment list

ENDPOINTS:

POST /api/assignments/
  Summary: Assign asset to employee
  Access: Admin only (manage:assignments privilege)
  Request Body: application/json
    {
      "user_id": "employee-uuid",
      "asset_id": "asset-uuid"
    }
  Response: 201 Created
    {
      "id": "uuid",
      "user_id": "employee-uuid",
      "asset_id": "asset-uuid",
      "assigned_date": "2024-03-07T10:30:00Z",
      "return_date": null,
      "user": {...},
      "asset": {...}
    }
  Errors:
    - 404 Not Found: User or asset not found
    - 400 Bad Request: Asset not available, user inactive
    - 403 Forbidden: Only admins can assign

PATCH /api/assignments/{id}/return
  Summary: Process asset return
  Access: Admin only (manage:assignments privilege)
  Path Parameters:
    - id (UUID): Assignment unique identifier
  Response: 200 OK
    {
      "id": "uuid",
      "user_id": "uuid",
      "asset_id": "uuid",
      "assigned_date": "2024-01-15T09:00:00Z",
      "return_date": "2024-03-07T14:30:00Z",
      "user": {...},
      "asset": {...}
    }
  Errors:
    - 404 Not Found: Assignment not found
    - 400 Bad Request: Already returned

GET /api/assignments/{id}
  Summary: Retrieve specific assignment details
  Access: Authenticated users (view:assignments privilege)
  Path Parameters:
    - id (UUID): Assignment unique identifier
  Response: 200 OK
    { assignment object with user and asset details }

GET /api/assignments/
  Summary: List all active assignments (no return date)
  Access: Authenticated users (view:assignments privilege)
  Query Parameters:
    - active_only (boolean, default=true): Filter active only

  Response: 200 OK
    [
      {
        "id": "uuid",

ENTITY 5: DASHBOARD (Aggregated Statistics & Metrics)
================================================================================

ENDPOINT: GET /api/dashboard/
Tags: [Dashboard, Analytics]
Summary: Retrieve system-wide statistics and metrics
Access: Admin only (view:dashboard privilege)
Response: 200 OK
  {
    "total_assets": 1248,
    "total_users": 450,
    "available_assets": 215,
    "assigned_assets": 892
  }
Business Logic:
- total_assets: COUNT(assets) WHERE is_active=true
- total_users: COUNT(users) WHERE is_active=true
- available_assets: COUNT(assets) WHERE status='Available'
- assigned_assets: COUNT(assets) WHERE status='Assigned'

================================================================================
ENTITY 6: ASSET_STATUS_LOG (Audit Trail for Status Changes)
================================================================================

DATABASE MODEL: asset_status_logs
DESCRIPTION: Immutable audit log tracking all status changes for compliance
and forensic analysis.

FIELDS:
- id (UUID, Primary Key): Unique identifier
- asset_id (UUID, Foreign Key → assets.id): Related asset
- old_status (String, Nullable): Previous status
- new_status (String, Required): New status
- changed_at (DateTime, Auto): Change timestamp

AUTOMATED LOGGING:
- Asset assignment triggers log entry
- Asset return triggers log entry
- Manual status change triggers log entry

READ-ONLY ACCESS:
No direct CRUD endpoints. Accessed via asset relationship:
GET /api/assets/{id}?include_logs=true

DATABASE SCHEMA (PostgreSQL)
================================================================================

TABLE: roles
CREATE TABLE roles (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR UNIQUE NOT NULL,
    permissions VARCHAR[] DEFAULT '{}',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

TABLE: users
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    role_id UUID REFERENCES roles(id),
    name VARCHAR NOT NULL,
    email VARCHAR UNIQUE NOT NULL,
    hashed_password VARCHAR NOT NULL,
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

TABLE: assets
CREATE TABLE assets (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    asset_tag VARCHAR UNIQUE NOT NULL,
    name VARCHAR NOT NULL,
    status VARCHAR DEFAULT 'Available',
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

TABLE: assignments
CREATE TABLE assignments (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    asset_id UUID REFERENCES assets(id) ON DELETE CASCADE,
    assigned_date TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    return_date TIMESTAMP
);

TABLE: asset_status_logs
CREATE TABLE asset_status_logs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    asset_id UUID REFERENCES assets(id) ON DELETE CASCADE,
    old_status VARCHAR,
    new_status VARCHAR NOT NULL,
    changed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
